1.2   Baseline

  • UFR: UFR introduces a post-processing re-rank method to directly modify the recommendation results of a given backbone recommendation model
  • S-DRO: S-DRO provides an in-processing solution that simply minimizes the value of the loss function of disadvantaged users during model training.
  • In-UCDS: In-UCDS introduces an in-processing method that lets disadvantaged users learn from advantaged users based on the approach of the dominant sets.

1.3   Backbone Models

  • MF: Matrix Factorization maps both users and items to a joint latent factor space and calculates the similarities among users and items.
  • NeuMF: Neural Collaborative Filtering introduces a deep neural network with non-linear activation functions to train a user and item matching function.
  • VAECF: Variational Autoencoders for Collaborative Filtering proposes a generative model with multinomial likelihood and uses Bayesian inference for parameter estimation.
  • LightGCN: Light Graph Convolution Network simplifies the design of GCN by including only the most essential component in GCN neighborhood aggregation — for collaborative filtering.

2   Diff4Rec: Sequential Recommendation with Curriculum-scheduled Diffusion Augmentation

  • 用Latent Diffusion model来进行数据增强。
    • 具体而言，先用一个VAE把user-item矩阵编码成latent vector，之后用diffusion学习
    • inference时先加噪再去噪，最终得到新的user-item矩阵。
    • 根据新的矩阵随机替换原来用户交互的item并shuffle，得到K个新的交互信息。
    • 再利用Curriculum Learning逐渐喂进backbone，用next prediction loss来训练。

一些问题

  • 要不要shuffle：（感觉要shuffle，因为模型对序列顺序信息不是很敏感）
  • 还是不明白为什么diffusion可以用来做数据增强，看画出来的图是把原来稀疏的user-item矩阵变得稠密了，但是为什么不是生成一个和原来一样的图

3   Context Matters: Enhancing Sequential Recommendation with Context-aware Diffusion-based Contrastive Learning

也是用diffusion做数据增强

  • 上一篇工作增强的目的是丰富user-item交互信息，然后随机替换原交互信息得到新的样本
    • 就推荐backbone而言，这里是看作了一个分类任务，模型直接输入下一次推荐中每个item的概率，所以这里没有embedding的概念。
    • 这里好像没有用到序列信息，因为有shuffle操作
    • 离散信息连续化是通过VAE实现的
  • 这篇工作是直接替换交互的sequence。
    • 就推荐backbone而言，这里看作是一个embedding任务，通过各种手段对item和user交互信息做编码，将交互信息embedding与item embedding点乘来得到下一次预测，这里有embedding的概念，就需要用对比学习+数据增强来得到更好的编码。
    • 具体而言，认为在替换交互信息时交互的上下文比较重要，所以会把完整的序列信息输入Bert，只替换一部分元素，剩下一部分元素作为context or condition辅助生成。
    • 生成的新序列没有用于next prediction，而是用来做对比学习。
    • 离散信息连续化是通过对embedding的round和embedding map实现的。

4   In-processing User Constrained Dominant Sets for User-Oriented Fairness in Recommender Systems

In-UCDS

目的是解决用户端不公平

现有的策略主要分为三类

  • 预处理：减少数据中的偏差bias
  • 训练中处理：模型训练时考虑公平性
  • 后处理：对推荐结果进行重排达到公平性

本文的想法是让劣势用户向优势用户学习，有两个问题

  • 如何找到劣势用户相似的优势用户？
  • 如何让劣势用户向优势用户学习？

分别俩措施

  • 训练前为每一个劣势用户构建一个constrained dominant set，这是一个图聚类算法。
  • 训练时让劣势用户的embedding与最相似的K个优势用户的embedding平均值接近，作为额外的fair loss

5   Hypergraph Convolutional Network for User-Oriented Fairness in Recommender Systems

与上文同一个作者，思路是类似的，都是在backbone的embedding上做文章，加入fair loss约束训练。

这里借用了Hypergraph与卷积的思路，定义了两种图，在训练过程中将backbone得到的embedding进行卷积来聚合邻居信息，得到新的embedding。

  • Inner-Group Hypergraph: 劣势用户内部的超图，劣势用户之间的关系
    • 认为到同一个item距离小于K的用户有相似关系，以此构建出图
    • 这里在进行卷积得到新的embedding后需要与原embedding用attention加权
  • Cross-Group Hypergraph: 劣势用户与优势用户之间的超图，劣势用户与优势用户之间的关系
    • 为每个劣势用户找到K个最相似的优势用户，构建出图

每个epoch训练流程如下

  • 构建Inner-Group Hypergraph内部图，卷积得到劣势用户新的embedding
  • 用劣势用户新embedding与优势用户旧embedding过backbone，计算推荐loss
  • 构建Cross-Group Hypergraph外部图，卷积得到优势用户新的embedding，将其与劣势用户的embedding做差得到公平性loss，想让两组embedding尽可能相似，从而进行学习。

6   Intra- and Inter-group Optimal Transport for User-Oriented Fairness in Recommender Systems

引入最优传输的概念 一样的思路，构建内部图和外部图。

  • 内部图是用来让劣势用户内部相互学习，以弥补数据的稀疏性。
    • 上一篇建图是根据与item的距离。
    • 这一篇把劣势用户均分为两个集合，根据最优传输理论进行一对一的匹配，匹配到的pair共享训练数据
  • 外部图是用来让劣势用户向优势用户学习
    • 上一篇是为每个劣势用户找相似的K个优势用户。
    • 这一篇是以优势用户为中心聚类
    • 最终的fair loss都是劣势用户与优势用户embedding的差值。

还有两个新的东西

  • 用一个数学定理证明了，要想劣势用户正确率被优势用户正确率以及两个集合的一个距离bound住
  • 原先的UOF指标只看两个集合正确性的差值，文章新提出一个指标，防止模型降低优势用户的正确率来提高指标。
    • 不过已经有了整体正确率，这个指标的提出感觉没啥意义（
